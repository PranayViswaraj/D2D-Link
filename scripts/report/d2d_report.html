01 Executive summary

Making two separate dies talk as if they were one chip

Processors are increasingly built from chiplets: several small dies in one package instead of one large die. The dies still have to exchange bus traffic. D2D-Link is a die-to-die link controller in synthesizable SystemVerilog. It takes AXI4 traffic on Die A, packs it into 128-bit CRC-protected packets called flits, sends them over a 32-bit lane and rebuilds the same transactions on Die B. When a flit is corrupted or dropped, the link recovers on its own.

The problems a die-to-die link must solve

  • There are few wires between dies, so a wide bus must be packed into small packets and sent in beats.
  • Bits flip and packets are lost. The link must detect this and resend, in order, without duplicates.
  • The receiver has a finite buffer. The sender must never overflow it, even while resending.
  • Each side runs on its own clock. Data must cross unrelated clocks without being corrupted.
  • The link must start up, notice a bad channel, retrain, and give up cleanly if it cannot recover.

What was built

  • A specification, microarchitecture, CDC report and verification plan, written before the RTL.
  • Synthesizable RTL: AXI adapters, a link layer (flit TX/RX, replay buffer, credits, training FSM), async FIFOs and APB registers.
  • A pyuvm testbench (Python UVM) with 14 constrained-random tests and fault injection on the lanes.
  • Formal proofs in SymbiYosys of the FIFO, credits, replay buffer, a reduced retry link and the FSM.
  • Lint, synthesis to SKY130 and a one-command Docker flow, using only open-source tools.

How the work was done

Why it matters

Die-to-die links are central to UCIe and to every chiplet product. This project takes one such link through the whole front-end flow (specification, RTL, clock crossings, UVM-style verification with fault injection, formal proofs, lint and synthesis) using only open-source tools. The interesting work is in the corner cases: a flit corrupted while the link is retraining, a lost NAK, a reset in the middle of a burst, three clocks at ratios nobody chose on purpose. The tests target exactly those cases.

Project status in one paragraph

Complete against its plan: phases 0 to 6 are committed and the working tree is clean. One real RTL bug was found by the tests and fixed. Three items are still open: the SystemVerilog UVM agent has been syntax-checked but never simulated (no SV-UVM simulator is available locally); the timing figure is an estimate, not sign-off; and the formal suite takes 709 s in total, over its 10-minute target, though every task is within its 5-minute cap.

02 Background and specification

What a die-to-die link is, and what this one supports

A large chip can be split into smaller dies that are cheaper to make and can be reused. The price is that signals which used to be on-chip wires now have to cross between dies through a small number of package wires. A die-to-die link controller hides that boundary.

Monolithic die versus chiplets

Three layers, bottom to top

Protocol layer UCIe: protocol

The AXI adapters turn the bus channels (AW, W, B, AR, R) into flit bodies and back again.

Link layer UCIe: D2D adapter

Adds sequence numbers, CRC, Go-Back-N retry, credits and training, and delivers flits in order with no loss.

Physical lane model UCIe: PHY

An ideal 32-bit parallel lane, 4 beats per flit. The testbench XORs bit flips into it and drops beats. There is no real PHY.

04 The flit

Everything crosses the link as a 128-bit flit

A flit (flow-control unit) is a fixed-size packet. A fixed size keeps the hardware simple: the receiver always knows where a flit ends, and the CRC always covers the same bits. Every flit has a 40-bit header, a 72-bit payload and a 16-bit CRC.

ACK and credit fields are running totals (mod 256) carried on every flit, so losing one flit never loses an ACK or a credit. The next good flit brings the up-to-date value.

Four beats on a 32-bit lane

One beat per clk_link cycle, most significant beat first. sof marks beat 0 so the receiver can realign. A flit cut short is counted as an error and triggers a NAK. The transmitter always sends something: IDLE, ACK or CREDIT flits fill gaps and keep ACKs and credits flowing.

CRC-16: catching corrupted flits

The transmitter runs the 112 header and payload bits through CRC-16/CCITT-FALSE (polynomial 0x1021, initial value 0xFFFF, no reflection, no final XOR) and appends the result. The receiver recomputes it. If it does not match, the flit is dropped and a NAK is sent.

CRC-16 is guaranteed to catch any 1, 2 or 3 flipped bits and any burst of up to 16 bits, so the tests inject only those patterns. In hardware it is one combinational XOR tree (rtl/common/crc16.sv), checked against a Python model on 1,004 random and corner-case vectors.

05 Link layer internals

Inside the link layer: a transmitter, a receiver and a memory of what was sent

The link layer is where reliability lives. The transmitter keeps a copy of every data flit until the other die acknowledges it. The receiver checks every flit and tells the transmitter what arrived, what was lost and how much buffer space has been freed.

Figure 2. Link layer internals (docs/microarch.md §2). Teal: data and credits. Orange: retry control. Amber: training and CDC.

What the transmitter sends, in priority order

a
TRAIN while the link is training or retraining.
b
NAK if the receiver has requested one.
c
The replay buffer entry at rd_seq, if there is one not yet sent. That covers new data and resends.
d
ACK if the acknowledged value has changed.
e
CREDIT if a freed-credit count has changed.
f
IDLE otherwise. The lane is never silent while training or active.

Enqueue is separate: each cycle at most one flit body moves from a TX FIFO into the replay buffer. That needs buffer space, a credit for its channel, and a link that is not in RESET or FAILED. Enqueue assigns SEQ = wr_seq and spends the credit.

06 Reliability: retry and credits

Go-Back-N retry and credits: nothing lost, nothing overflowed

Two mechanisms make the link reliable. Retry guarantees every data flit arrives exactly once and in order. Credits guarantee the sender never overruns the receiver's buffer. Both are formally proven.

Go-Back-N retry, in action

Every data flit gets a sequence number and a copy stays in the replay buffer until it is acknowledged. A bad or out-of-order flit makes the receiver send a NAK, and the transmitter goes back and resends everything from that point. If a flit simply disappears and nothing follows it, a replay timeout triggers the same rewind.

The replay buffer: three pointers

The rule is ack ≤ rd ≤ wr and wr − ack ≤ 16. There are 256 sequence numbers and the window is 16, less than half, so the receiver can always tell a duplicate (drop it) from a gap (NAK it). This invariant is formally proven.

Credits: never overflow the receiver

A credit is one free slot in the receiver's buffer, and the transmitter may only enqueue while it holds one. Request and response channels have separate credits, so a jammed request path can never block the responses that would clear it. That removes the classic request/response deadlock.

Three design decisions worth remembering

Cumulative, not incremental

ACK and credit fields carry running totals (mod 256). If the flit carrying them is lost, the next good flit has the up-to-date total, so a credit or ACK can never leak away.

Credits are spent once

A credit is consumed when a flit enters the replay buffer, not each time it is sent. Replays never spend credits again, so an in-order flit always finds a free slot (asserted in RTL).

Headers filled at send time

The replay buffer stores only the 80-bit body. SEQ, ACK, credits and CRC are added as the flit goes out, so a replayed flit carries fresh ACK and credit values.

07 Link training and clock-domain crossing

Bringing the link up safely, and moving data between unrelated clocks

Before any data flows, both dies must agree that the link works. Each side sends TRAIN flits; after 8 good ones in a row it is locked and says so in its own TRAIN flits. When both sides are locked the link goes ACTIVE. Too many errors send it back to RETRAIN, and too many failed attempts end in FAILED.

Figure 3. Link training state machine. All 5 states and 11 transition arcs are covered by the regression; ACTIVE-only-with-lock and FAILED-only-after-budget are checked by bounded model checking.

No data is lost across a retrain

Retraining never touches the replay buffer, sequence numbers, credits or receive FIFOs. On return to ACTIVE the transmitter replays everything unacknowledged and the receiver drops duplicates. A TRAIN flit with LOCKED=1 arriving while ACTIVE is ignored: without that rule the two dies could keep knocking each other back into training forever.

How a safe clock crossing works

Sampling a changing multi-bit value from another clock can capture a half-updated number. Gray code changes exactly one bit per step, so a sampled pointer is always the old or the new value, never a random third. The FIFO is formally proven with two unconstrained, unrelated clocks.

Why gray code

Counters never cross bit by bit. The link domain pushes a complete status snapshot through a FIFO, so a register read is coherent and only a few clocks stale. Credit return reuses the receive FIFO's already-synchronized read pointer, so it needs no extra crossing. It lags by 2–3 cycles, so credits come back late, never early.

08 A transaction's journey

Following one AXI write burst from the host to memory and back

This is the whole design working together. A write burst is broken into flits on Die A, carried across the lane with sequence numbers and CRC, rebuilt into AXI on Die B, and its response travels back on the other virtual channel. The ACK for the request rides on the response flits.

Figure 4. Sequence of one 4-beat write. Reads work the same way, with the R beats returning as RSP_DATA flits. If a flit in step 5 is corrupted, Die B sends a NAK and Die A replays from that flit; the host only sees a slightly later B.

Why one transaction at a time at Die B?

Die B executes requests strictly in arrival order, one at a time. That is legal AXI, keeps the ordering argument trivial and lets the scoreboard predict every response exactly. The cost is throughput. It is documented as a limitation; per-ID reordering would be the next feature.

Adapter rules

Die A accepts an AW only with fewer than 4 writes outstanding, and an AR only with fewer than 4 reads. AW and AR are never accepted in the same cycle, so the request order is the handshake order. Die B asserts BREADY and RREADY only when the response FIFO can take the flit.

11 Findings, limitations and next steps

What the tests found, what the design does not do, and what comes next

The bug log keeps the record honest. Real RTL defects are listed separately from testbench mistakes and from behaviour that only looked like a bug.

The real RTL bug: AXI READY high while still in reset

The pin reset deasserts 2 clocks before the internally synchronized reset. In that window the slave adapter built AWREADY from reset-state values, so it read 1. A host that started right after reset completed an AW handshake that the still-in-reset flops never captured: the W beats were never accepted and the bus hung. apb_csr.pready had the same flaw.

Caught by reset_during_traffic, seed 112. Fix: gate AWREADY, ARREADY, WREADY and PREADY with the synchronized reset. Lesson: every combinational handshake output must be qualified by the domain's synchronized reset, not only its registers.

Looked like a bug, was the specification

At a uniform 3% flit error rate the link went to FAILED. The retrain threshold is more than 8 bad flits per 256 (about 3.1%), so 3% regularly crosses it, retrains recur, the budget of 4 runs out and FAILED follows, exactly as specified. crc_error_retry now injects 1%; escalation is covered by its own tests. The thresholds encode a bit-error-rate budget, and the registers make it tunable.

Testbench bugs 5, none weakened a check

Known limitations docs/spec.md §9

  • Throughput: Die B runs one transaction at a time, with no per-ID reordering.
  • Efficiency: one flit per AXI beat: 80 useful bits of 128, 4 link cycles per beat.
  • Scope: only INCR bursts verified; no exclusive access, QoS, cache or prot signals.
  • Reset: both dies assumed to reset together; no single-die reset mid-traffic.
  • Recovery: FAILED needs software to toggle ENABLE (traffic is preserved).
  • PHY: ideal parallel lane; no deskew, scrambling or lane repair; framing trusted.
  • SV-UVM: uvm_sv/ is syntax-checked only, never simulated locally.
